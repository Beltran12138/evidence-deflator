Evidence Deflator · 最小案例数

你的判断质量，需要多少次决策才看得出来

「我这次判断对了吗」答不了——单次结果是一次抽样。「我这套方法有没有优势」答得了，但它要求样本。 这个页面把后一句话变成一个具体的数字：在你做第一笔交易之前就能算出来，不需要任何收益数据。 全部计算在本地完成，不上传、不注册、无后端。

一、基准：先让 p₀ = 0.5 成立

从 N 个候选里随机抽一个，它高于这 N 个的中位数的概率恰好 0.5——这是定义，不是假设。换成市值加权指数或均值，因为右偏，这个概率天然低于 0.5。
不是你觉得自己有多少，是你希望这次检验有能力发现的最小优势。填得越接近 p₀，需要的样本越多，而且是平方级。

二、样本的真实成色

同一条主线买五个标的 = 一个判断五笔交易。填 1 表示每笔交易都是彼此无关的独立判断。
同簇内两笔的结果相关程度。测出来就填测的，拍的就记成拍的——本页会在下方如实标出。
改归因框架、换基准、调「算不算成立」的门槛，每换一次算一次。最终采用的那套是从 k 套里挑出来的，它跨过门槛这件事有一部分来自挑选本身。

    这个数字的诚实边界

    • 正态近似。大样本近似；结果 < 20 时应改用精确二项，本页会在结果处提示。
    • Kish 折算是乐观的下界。它假设簇与簇之间不相关，而真实组合还有共同的市场 Beta 穿过所有簇。算进去只会更少，不会更多。
    • ρ̄ 和 p₀ 本身要估，而估它们也要样本。这个循环绕不过去，只能申报——上面那个下拉就是用来申报的。
    • 别拿今天的榜单去反推 p₀。死掉的标的已经不在榜单里了，用现存 top-N 测出的「随机抽一个跑赢基准的概率」必然偏高。这个测量本身就带幸存者偏差。要用「跑赢 BTC」当基准，就得用当期快照的候选集去测，并申报候选集怎么来的；测不出来就别假设，改用中位数基准。
    • 这里测的是「在给定候选集里选得准不准」。「候选集本身选得对不对」是另一个决策，不在这个检验里，要单独记——否则两个信号互相掩盖。
    • 本页回答「够不够」，不回答「行不行」。算出一个很大的数，不等于你的方法没用；等于到目前为止，证据还不足以让任何人（包括你自己）判断它有没有用。
